=== Test the navigation ===
1. On the homepage I clicked "انتقل إلى كورسات هذا الشهر" (href="#this-month").
   The page jumped to the section with id="this-month" and the address ended with #this-month.
2. I opened the schedule page from "المواعيد" in the nav (href="pages/schedule.html").
3. On the schedule page I clicked "الرئيسية" in the nav and it took me back to index.html.

=== href used for the return trip ===
href="../index.html"

=== Why the path starts from the pages folder ===
A relative path starts from the folder of the file that contains the link.
The link is written in pages/schedule.html, so the browser starts looking from the pages folder.
index.html is not inside pages; it is one level up, in the session-5 folder.
So "../" is needed to go up one folder from pages to session-5, and then index.html is found there.
If I wrote href="index.html", the browser would look for pages/index.html, which does not exist.

Session 5 - Question 3 - Answers

=== Clicking the full-name label ===
I opened pages/enquiry.html in the browser and clicked the label text "الاسم الكامل".
The cursor moved into the full-name field, because the label's for="full-name" matches the field's id="full-name".
Then I typed a sample name (سامي خالد) and changed the seat count from 1 to 3.

=== placeholder vs value ===
The name example "مثال: أحمد محمد علي" was a placeholder: it only showed as a hint while the field was empty,
and it disappeared as soon as I started typing. It is not a real value, so it is never sent with the form.
The seat count 1 was set with value: it is a real value written inside the field. I could edit it,
and if I did not change it, 1 would be sent with the form.

=== Which seat count would the form submit now? ===
The form would submit 3 (seats=3), because I changed the value from 1 to 3 and the form sends the current value of the field.
