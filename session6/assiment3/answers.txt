Bug 1 - h2 font size (unit test)
========================================================
Observed before the fix: In Computed, the h2 "CSS Foundations" had font-size 30px instead of 24px.
For this reading: styles.css was loaded, the root (html) font size was 16px, and the card's font size was 20px.
Line that caused it:
  .course-card h2 { font-size: 1.5em; }
Effect: em is relative to the font size of the parent element. The h2 is inside .course-card, which has
font-size 20px, so 1.5em = 1.5 x 20px = 30px.
Fix:
  .course-card h2 { font-size: 1.5rem; }
rem is relative to the root font size (html), so 1.5rem = 1.5 x 16px = 24px.
Test after the fix: In Computed, the h2 font-size was 24px.
For this reading: styles.css was loaded, the root font size was still 16px, and the card's font size was still 20px.

Measurements:
- Before (1.5em): 30px
- After (1.5rem): 24px

Bug 2 - --brand color on h1 and h2
========================================================
Observed before the fix: The h1 "coderz Institute" was tomato (red-orange), and the h2 was the body text
color #24364b, not the brand color #12546c.
Lines that caused it:
  h1, h2 { color: var(--brnad); }
  <h1 style="color: tomato;">coderz Institute</h1>
Effect:
- --brnad is a spelling mistake. The variable defined in :root is --brand, so var(--brnad) has no value.
  The color declaration becomes invalid, and the h2 inherits the color of its parent instead (#24364b from body).
- The inline style on the h1 has higher priority than any rule in the external CSS file, so even with the
  correct variable, the h1 would stay tomato.
Fix:
  h1, h2 { color: var(--brand); }
and I removed the inline style: <h1>coderz Institute</h1>
Test after the fix: Both h1 and h2 were #12546c (rgb(18, 84, 108)).
--brand test: I changed the value once in :root to a test color:
  --brand: #c2185b;
Both the h1 and the h2 changed to #c2185b (rgb(194, 24, 91)) together.
Then I restored the intended color --brand: #12546c; before submission.

========================================================
Bug 3 - View schedule link color on hover
========================================================
Observed before the fix: When I moved the mouse over "View schedule", its color did not change.
It stayed #12546c.
Line that caused it:
  .action :hover { color: #6845a8; }
Effect: The space between .action and :hover makes it a descendant selector. It means
"an element in hover state inside .action", not ".action itself in hover state". The link has no
child elements, so the rule matched nothing.
Fix:
  .action:hover { color: #6845a8; }
Test after the fix: I moved the mouse over the link and it turned #6845a8 (rgb(104, 69, 168)).
When I moved the mouse away, it returned to #12546c.
